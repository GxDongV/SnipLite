# 体积优化后续验收记录

日期：2026-11-17。分支：`codex/package-size-runtime-audit`。本轮按照 `PACKAGE_SIZE_TARGET.zh-CN.md` 补充本机验收，并按用户确认生成离线验收包。干净 Windows 10/11 环境暂不可用，相关检查转到离线包执行，不标记为已完成。

## 1. 修复覆盖安装后体积不下降

实际升级测试发现：Inno Setup 会覆盖新文件，但旧版本独有的 DLL 仍留在安装目录。由正式 v0.3.14 文件集升级时，两个设计器实现仍占用约 5.83 MiB；由 v0.3.13 升级还会遗留 WPF 和 SDK/WinRT 文件。

新增 `packaging/windows/ObsoleteRuntimeFiles.iss` 并从安装器的 `[InstallDelete]` 引入。名单仅包含两轮发布审计确认弃用的 37 个 DLL，没有通配符；每项都在编译时检查新发布目录是否还包含该文件，包含时不生成清理项。因此关闭设计器精简或未来运行时重新带入依赖时，不会清理本次仍需分发的文件。应用数据、未知文件和用户文档不在清理名单中。

本机使用独立 AppID、独立目录和禁用快捷方式/程序自启动的静默验收包，保留正式安装。验证结果：

- v0.3.14 文件集升级到精简候选，逐文件哈希核对通过，无两个设计器残留。
- v0.3.13 文件集升级到精简候选，无名单内的旧依赖残留；测试用户文件在升级及卸载后保留。
- 默认、ultra、ultra64 各 3 次全新静默安装和卸载通过，安装文件逐项哈希一致，卸载后验收 AppID 和程序文件移除。
- 隔离配置文件哈希不变；正式配置指针已恢复，原本运行的已安装程序已恢复。

独立 AppID 的本机安装测试不代替干净系统中运行正式安装器的验收。离线包使用正式 AppID 的原包，并在检测到已有 SnipLite 实例或安装注册时拒绝执行。

## 2. 三种入口的启动和空闲内存

旧版为正式 v0.3.14，候选为上一轮设计器精简产物；分别测量便携、单文件和隔离安装目录的正式 EXE，共 60 次。每组 5 次新缓存路径启动和 5 次复用同一路径启动。每次都是新进程，没有清空 Windows 文件缓存或重启操作系统，因此不是操作系统意义上的完全冷启动。

就绪标准为程序写出本次完整启动日志并进入输入空闲；随后等待 3 秒采样空闲内存。测试配置禁用快捷键和通知，模型未加载。未从共享 .NET 运行时目录加载模块；这仍不能代替无 SDK 环境的验证。

没有达到规划中“中位数同时增加超过 10% 和 50 ms”的人工复核阈值。仅能说明此场景没有明显启动回退，不宣称启动更快或内存更低；3 秒空闲采样不等于长时间稳态或泄漏测试。

单文件本次托盘启动的 10 次候选和 10 次基线测量均未在指定释放路径生成文件，测得释放占用为 0 字节；单文件清单没有原生文件类型条目。不要由 `IncludeNativeLibrariesForSelfExtract=true` 推断每个构建都必然释放文件，也不将该结果推广到依赖升级后的版本。原生项是否需要释放应按实际发布内容和运行结果确认，参见 [.NET 单文件发布文档](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/)。

后续最终构建仅更新了源码提交版本元数据及安装器逻辑。主程序 1,741 个方法的签名和 IL 与正式 v0.3.14 相同；最终回归程序和最终候选的 `SnipLite.dll` 哈希一致。没有将最终构建重新进行 60 次测量，原始测量件路径和记录保留在 `.local/package-acceptance/startup/`。

## 3. 安装器压缩取舍

使用同一份精简文件、独立 AppID，测量编译进程树及每档 3 次全新安装。采样间隔 25 ms，峰值为安装器/编译器及其子进程工作集合计；安装耗时包含启动和注册，不是纯解压 CPU 时间。

| 指标 | 默认 LZMA2 | ultra | ultra64 |
| --- | ---: | ---: | ---: |
| 验收安装器字节数 | 63,064,140 | 62,682,442 | 62,474,040 |
| 相对默认减少 | — | 0.36 MiB | 0.56 MiB |
| 编译耗时，单次 | 19.85 秒 | 24.04 秒 | 28.93 秒 |
| 编译进程树峰值工作集 | 126.31 MiB | 402.32 MiB | 706.32 MiB |
| 3 次安装耗时中位数 | 5.294 秒 | 5.319 秒 | 5.515 秒 |
| 安装耗时范围 | 5.254–5.334 秒 | 5.277–5.335 秒 | 5.271–9.573 秒 |
| 安装进程树峰值工作集中位数 | 46.34 MiB | 70.45 MiB | 102.49 MiB |

默认保持 `Compression=lzma2`。高压缩级别减少不足 1%，构建和安装峰值内存明显增加；ultra64 的一次安装还出现明显抖动，没有理由将其设为默认。各档新安装目录均为 149,489,119 字节（142.56 MiB，含卸载器），卸载器、AppID/名称使用的是隔离验收配置，不当作正式包干净安装的精确字节数。参数定义参见 [Inno Setup Compression](https://jrsoftware.org/ishelp/topic_setup_compression.htm)。
