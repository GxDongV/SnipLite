日期：2026-11-17。分支：`codex/package-size-runtime-audit`。源码提交：`e8a7e78`。本轮继续执行 [体积优化规划](PACKAGE_SIZE_TARGET.zh-CN.md) 中的资源增长复查，不再在用户桌面运行循环显示截图/贴图的压力测试。

## 1. 已定位并修复的问题

- `CaptureForm` 只有 `OnFormClosed` 释放截图、标注/翻译位图、计时器和光标。未显示窗体直接 `Dispose` 的路径会跳过清理。现由关闭和销毁共同调用一次性的资源清理，同时使后台识别结果失效并取消翻译。
- `PinForm` 直接销毁时没有移出静态 `Open` 列表，原图和计时器也未释放。现统一清理，重复销毁安全；未显示的贴图不会新增历史记录。
- 普通关闭贴图时，右键菜单没有销毁。菜单订阅全局主题事件，菜单项又引用贴图，因此即使移出 `Open`，整个贴图对象仍被持有。现显式关闭菜单，并在下一次 UI 消息循环销毁，解除主题订阅。
- 贴图更新设置时释放被替换的界面字体；菜单持有并释放自身创建的字体。托盘菜单改为直接传入其专用字体，避免先创建再覆盖默认字体。

保留了菜单关闭栈退出后延迟销毁的机制。有 WinForms 同步上下文时延迟到下一轮，没有 UI 上下文时直接释放，不再静默丢弃清理。未改变 OCR 引擎、模型、截图输出和贴图历史策略。

## 4. 首选项页面重建的资源释放

继续审计发现，`PreferencesForm.MakeChooser` 将菜单赋给按钮的 `ContextMenuStrip` 后，误以为菜单会随按钮销毁。WinForms 的这个属性允许共享菜单，不会自动处理菜单所有权。设置页每次重建虽然销毁了按钮，但菜单仍通过全局主题事件持有按钮、页面和首选项窗口。

修复为每个选择按钮明确绑定自己的菜单释放动作，仍使用上一轮的延迟销毁方法，避免在菜单选择/关闭调用栈中销毁 ToolStrip。同时统一首选项界面字体的所有权：更换字体或恢复默认时释放旧字体，退出窗体时在子控件清理后释放当前字体。没有更改设置项、下拉框的操作方式或保存策略。
