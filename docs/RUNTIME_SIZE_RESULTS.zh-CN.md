## 2. 两项落地调整

### 2.1 排除已审计的设计器实现

对发布 DLL 使用 `System.Reflection.Metadata` 检查程序集引用和成员引用，并检索主程序中的动态调用、编辑器发现和对话框入口。主程序不使用 `PropertyGrid`、设计宿主、`TypeDescriptor.GetEditor` 或设计器编辑器发现。普通控件上的 Designer/Editor 元数据不会因为渲染窗口就实例化设计器；本轮也实际打开并取消了字体、颜色及文件对话框。

只有以下两个实现文件被排除：

| 文件 | 字节数 | 审计版本 | SHA256 |
| --- | ---: | --- | --- |
| System.Windows.Forms.Design.dll | 6,092,584 | WindowsDesktop Runtime 10.0.12 / win-x64 | `4dc904431a32c5368b00708c6162f56c937ac2cdd7facfdec1d169b66ae8277d` |
| System.Windows.Forms.Design.Editors.dll | 16,168 | 同上 | `68cc0922bb12f17870f70fd559bd6e412da672a06fb0232b97bc12f5468c8966` |

`System.Design.dll`、`System.Drawing.Design.dll` 和 `System.Drawing.dll` 等兼容转发程序集保留。它们的一些设计器类型转发目标不再随包提供，因此今后若引入属性网格、设计宿主或编辑器发现，必须重新审计或关闭本项，不能直接沿用结论。

实现位于 `packaging/windows/RuntimeSize.targets`，由主项目导入。在发布阶段对准确的运行时资产路径做排除，重新生成 `.deps.json`，并阻止 SDK 将相同的构建拷贝项再次并入发布项；这些步骤都在目录拷贝和单文件生成之前执行。构建目录保持完整，没有发布后手工删除 DLL。

规则同时检查包 ID、10.0.12 版本和 SHA256。版本或哈希变化时保留未知组件并输出警告；已分别验证“准确匹配排除”“版本变化保留”“哈希变化保留”。新依赖默认保留。也验证了先关闭优化、再开启优化时不存在陈旧的依赖清单。

完整运行时回退方式：

```powershell
dotnet publish src/SnipLite/SnipLite.csproj -c Release -r win-x64 --self-contained true -p:SnipLiteReduceDesignerPayload=false -p:PublishTrimmed=false -o .local/full-runtime
```

### 2.2 便携 ZIP 使用 SmallestSize

`scripts/release.ps1` 改用 .NET 的 `ZipFile.CreateFromDirectory`。支持 `SmallestSize` 的 PowerShell 运行时使用该级别，旧运行时自动退回 `Optimal` 并打印实际使用值。仍是标准 ZIP，解压后的文件内容不变；先写独立临时文件，成功后替换目标 ZIP。

在相同的精简目录上，各测 3 次（.NET 10.0.12，单独进程），每次都解压并逐文件核对 SHA256：

| 指标 | Optimal | SmallestSize |
| --- | ---: | ---: |
| ZIP 字节数，3 次均相同 | 76,220,899 | 74,572,224 |
| 压缩耗时中位数 | 2.294 秒 | 5.545 秒 |
| 压缩耗时范围 | 2.288–2.362 秒 | 5.535–5.558 秒 |
| 解压耗时中位数 | 0.474 秒 | 0.546 秒 |
| 解压耗时范围 | 0.462–0.480 秒 | 0.545–0.559 秒 |
| 测试进程峰值工作集范围 | 38.88–40.99 MiB | 39.04–39.84 MiB |

峰值是包含压缩、解压和哈希核验的整个测试进程工作集，不是压缩器独占分配。相对本轮保留 Optimal 的包，压缩级别额外减少 1,648,675 字节（1.57 MiB）；相对正式 v0.3.14，设计器排除和 ZIP 参数合计减少 3.43 MiB。安装器继续使用原有 LZMA2，没有增加字典；未取得安装耗时和内存实测前不调整它。

## 3. 保留项与约束

- 保留 PP-OCRv6 Small、方向识别模型及 SimdPaddleOCR 引擎。OCR 相关四个程序集与正式 v0.3.14 的 SHA256 一致。
- 保留 `Microsoft.CSharp` 和 `System.Linq.Expressions`：管理员启动设置使用动态 Task Scheduler COM，主程序存在真实的 RuntimeBinder 成员引用，回归也实际加载了它们。
- 保留 `Microsoft.VisualBasic.*`：已审计其程序集关联，但尚未完成所有延迟路径的排除证明，不以“主项目是 C#”作为删除依据。
- 保留 `Microsoft.DiaSymReader.Native`、DAC/DBI、转储工具等诊断组件，没有取得足以证明不影响故障诊断的证据。
- 保留 WinForms、.NET 运行时、八语言资源、README、预览图与许可证。不启用裁剪、AOT、模型联网下载，不改变界面或功能。
- 维持 .NET SDK 10.0.401 / Runtime 10.0.12、现有 NuGet 版本、Windows 10 19041 下限和发布架构。没有通过升级运行时制造不同口径的差额。

## 4. 构建与包内容审计

最终构建命令（从仓库根目录执行）：

```powershell
./scripts/release.ps1 -OutputRoot "$PWD/.local/runtime-size-optimization/final" -IsccPath "$PWD/.local/tools/inno/ISCC.exe"
./scripts/release.ps1 -OutputRoot "$PWD/.local/runtime-size-optimization/repeat" -IsccPath "$PWD/.local/tools/inno/ISCC.exe"
```

使用现有 Inno Setup 6 工具。构建输出无警告、无错误。两个独立目录都生成了三种包：

- 便携目录从 267 个文件降为 265 个，逐文件内容一致；相对正式 v0.3.14，只有两个设计器文件退出，`.deps.json` 相应更新。其余所有文件（含主程序）哈希一致。
- 单文件清单从 209 项降为 207 项，两轮 EXE 的大小和 SHA256 完全一致；各清单项与便携目录对应内容一致，部署元数据按 SDK 单文件格式单独检查。
- 两轮 ZIP 大小相同，每个条目的解压哈希与便携目录一致；ZIP 文件本身的哈希因文件时间元数据不同而变化。
- 两轮安装器分别为 63,063,712 和 63,063,706 字节，相差 6 字节。两次使用相同、逐文件哈希一致的便携目录作为安装输入；尚未在干净环境实际安装后核验，不宣称安装后验收已完成。
- 目录、依赖清单和单文件清单均不含两个被排除的设计器实现；没有混入测试、日志、`video/` 或临时工具。

## 5. 功能和性能验证

| 项目 | 结果 |
| --- | --- |
| 截图、标注、二维码、首选项、自动框选、文字编辑、菜单悬停 | 主回归 172 项通过 |
| 字体、颜色、打开文件、保存文件、目录对话框 | 在本进程内实际显示并取消，全部通过；未加载设计器实现 |
| 管理员启动所需动态 COM | Task Scheduler 连接和读取根目录通过；没有创建或修改任务 |
| 手动复制，自动复制开/关，PNG/Bitmap，工具栏/快捷键等入口 | 16 项独立子进程读取系统剪贴板通过 |
| 翻译与 OCR 状态栏、选区、错误及取消 | 82 项通过；翻译服务采用模拟响应，没有重复请求在线服务 |
| F3 贴图、浅深主题、选区、文字重复编辑 | 各专项通过 |
| 原生 UIA、遮罩下按钮、停留重试、单击选择及回退 | 直接 COM 和完整截图流程回归通过 |
| 八语言 | 每语言 407 资源检查通过；自包含界面检查 3,452 项通过，布局候选溢出 0 |

## 6. 尚未完成的整体验收与后续边界
